# Local verified-payment custody during cutover

Date: 2026-09-25. Backend base: `189277b`. Local implementation only: production bootstrap/title/realm guards remain closed. No provider API calls, live configuration, billing, migration, or deployment are part of this qualification.

## Contract

Close **new checkout only** with `XSOLLA_CHECKOUT_CLOSED=true`. Keep existing fulfillment global/family/SKU gates active for previously issued tokens and callbacks. Do not use `PURCHASES_GLOBAL_ENABLED=false` or family/SKU shutdown as the migration procedure: those gates precede verification/admission and would reject paid callbacks.

The existing signature, project, authenticated user, immutable catalog, amount/currency/quantity and Starter reservation verification remain in place. A verified accepted receipt is appended and fsynced to the bounded holding inbox **before the first authority query**. An HTTP 204 promises durable receipt custody, not a spendable balance or completed purchase. Before-persist failure/crash has no acknowledgment and requires provider redelivery; no claim is made that an unacknowledged receipt in RAM survives process loss.

The original product version carried by an issued checkout token is validated against the immutable registry. Unknown, malformed or conflicting versions fail closed. Duplicate callback identity binds transaction, recipient, original plan/version/hash, amount and currency. Changing alias does not change economic identity. A conflicting duplicate never overwrites the original.

When authority is unavailable, Migrating or Blocked, the holding receipt stays pending. Recovery scans at most eight entries every two seconds with a rotating cursor. Each entry is re-read under ownership immediately before routing: a stale batch snapshot cannot bypass a handoff/legacy-attempt persisted while an earlier entry awaited I/O. V2 requires the existing private client to validate the durable admission/completion identity and hash. Only then does the holding inbox append its handoff. Timeout/lost response retains the original operation for idempotent redelivery. A positive V1 decision cannot bypass the durable migration fence. No V1 fallback is introduced.

A successful V1 receipt handoff is retained permanently and prevents a later duplicate callback from being sent to V2. Before any legacy receipt call a separate `legacy_attempt` record is fsynced. If its response/handoff is lost and authority has since become V2, the receipt remains `PAYMENT_LEGACY_HANDOFF_REQUIRES_RECONCILIATION`; it is **not** blindly submitted as a fresh V2 payment. The current API does not expose an authoritative imported-receipt proof for every legacy pending receipt. This is a remaining cutover qualification blocker, not automatic exactly-once completion.

## Ownership, capacity and operational limits

The existing holding file must be preprovisioned for bootstrap (`initialize:false`). A kernel-owned IPC endpoint derived from the canonical file path enforces one local process before admission or recovery: Windows named pipe, Linux abstract socket. A second owner fails closed. Kernel ownership is released on process death; no PID test, stale-lock deletion or guessed unlock is used. This is not a multi-host/cluster design. Windows process exclusion and actual kill/restart are tested; Linux runtime is not exercised here.

Default hard limits: 16 MiB, 4096 permanent identities, 1024 pending receipts. Each pending receipt reserves 1024 bytes for attempt/handoff evidence. Checkout closes at 75 percent of pending, identity or reserved-byte capacity, while late callbacks may use remaining headroom. Original identities are never evicted or expired; duplicates remain readable at capacity. Remaining capacity is finite and does not prove that every issued historical token fits. A migration operator must inventory/drain outstanding tokens and monitor capacity before enabling a cutover. A full or corrupt inbox returns failure without acknowledging a new receipt.

Rows have exact shapes, contiguous sequence/hash-chain and canonical receipt validation. Partial tails, corrupt hashes, duplicate and reordered rows fail closed. This does not claim detection of removal of a complete terminal suffix without a separate external anchor. Keep the holding file and authority fence protected and included in recovery backups. Do not delete, replace, prune or relocate them while running.

Explicit fixture initialization fsyncs the file, and the parent directory on Linux. Windows tests establish **process-crash** persistence only, not filesystem/controller power-loss guarantees. Production provisioning, power-loss durability, replicated storage, backup/restore and cluster ownership still require operational qualification.

Shutdown closes admission, stops scanning and waits for outstanding handoffs before releasing ownership. V2 HTTP is bounded by its existing client timeout. The legacy receipt adapter retains its existing timeout behavior: an indefinitely pending legacy promise can delay shutdown. The implementation deliberately does not unlock while a late write may still run; it does not claim universally bounded shutdown.
